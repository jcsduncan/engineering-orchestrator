# Bounded scheduling

`RunQueue` stores immutable issue snapshots in the same SQLite database as intake and run records. Pass each persisted active `IssueClaim` to `accept_claim()`: one transaction verifies the stored snapshot, enqueues its run ID once, and acknowledges dispatch. Repeating the call after a crash returns the same queue entry. `enqueue()` remains available for callers that do not use the issue claim store.

Call `run_queued()` with a controller-owned callback that invokes `run_task` using the snapshot's run ID. The callback receives a cancellation predicate; it must stop its worker when that predicate becomes true and return the partial result. While a run is active, the scheduler polls for newly enqueued work every second by default (`poll_interval`). It returns when idle; a long-lived producer calls it again when new work arrives. The worker, checks, worktree, and logs remain owned by the run controller.

Configure positive `max_running` and `max_per_repository` limits when opening the queue. Dispatch is ordered by insertion sequence and skips a repository at capacity so another eligible repository can start. Before dispatching an accepted issue claim, it rechecks the claim under the same SQLite write lock; a revoked claim is recorded as cancelled with its reason. Cancellation after dispatch still requires the controller to stop the worker. `request_cancel()` cancels queued work immediately and signals running work durably. The next `run_queued()` call preserves queued items and marks interrupted running items `needs_review`; it does not repeat uncertain execution. An interrupted run retains its capacity slot until the controller verifies its process and container are stopped, then calls `acknowledge_stopped()`. `finalized()` lists terminal queue entries only after their resource reservation has been released, allowing claim completion or cancellation acknowledgement to be replayed after a crash.

One scheduler loop holds an exclusive file lock. Queue mutations use SQLite transactions, so intake can add or cancel claims from another process. The callback must not receive GitHub publication credentials.
